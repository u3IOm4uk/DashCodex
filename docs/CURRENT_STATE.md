# Поточний стан

Оновлено: **2026-09-13**. Етапи 1–5, hierarchy ordering/tree animation, detail unit breakdown, інтерактивні графіки та конструктор міжкатегорійного порівняння інтегровані у стабільний `main`.

## Поточна реалізація

- Локальний статичний dashboard без backend; runtime не потребує npm/build-system.
- Excel validation виконується до parse; critical errors блокують імпорт, warnings лишають книгу доступною.
- `source.kind` відділений від filename.
- `aggregate()` використовує lazy indexes + bounded LRU cache без зміни числової семантики.
- `contour-view.js`, `contour-charts.js`, `contour-navigation.js` винесені окремо від основного orchestration.
- Sticky-категорії зберігають compact/pinned стан при зміні категорії; переміщується контент під ними.
- Change-scoped GitHub Actions є merge gate: syntax/regression/browser checks запускаються лише за релевантним diff.
- Playwright scopes: `core`, `sticky`, `charts`, `bps`, `units`; resource revision перевіряється окремо.
- `ContourConfig.UNIT_HIERARCHY` у `js/contour-config.js` є єдиним джерелом parent-зв’язків **угруповання → АК → підрозділ**; порядок Excel та naming heuristic не створюють зв’язків.
- `contour-units.js` відповідає за runtime-відображення дерева, expand/collapse, statuses та archive, але не визначає склад автоматично.
- Дочірні вузли у hierarchy view відображаються нижче parent за `UNIT_HIERARCHY`, мають tree-branch і плавний expand/collapse з підтримкою `prefers-reduced-motion`.
- Статуси `active / hidden / archived` зберігаються лише локально; архівування не змінює Excel або normalized records.
- У detail-вікні ГОЧ батьківський вузол з прямими дітьми отримує поденну таблицю з колонкою «Підрозділ»: спочатку власний рядок parent, далі тільки його безпосередні діти з `UNIT_HIERARCHY`.
- Глибші нащадки у detail-таблицю автоматично не підтягуються; parent і direct children читаються окремими `aggregate(..., group)` викликами, без сумування дітей у parent і без зміни normalized records.
- Для leaf-вузла detail-таблиця лишається без hierarchy breakdown.
- Hierarchy breakdown використовує ті самі базові стилі клітинок, типографіку та розділювачі, що й звичайна detail-таблиця; дочірній рівень позначається лише відступом назви.
- `#detail-dialog` ущільнений: локальний `sheet-heading` має `margin-bottom: 10px` (`8px` на mobile), а line/bar перемикачі розташовані праворуч в одному горизонтальному блоці з `Тенденція + період` на desktop; на телефоні дата має окремий ряд.
- Browser test перевіряє direct children, компактний відступ заголовка detail-dialog і горизонтальне розташування trend controls.
- Hover мініграфіків категорій і БпС показує дату/показник/значення; нуль і пропуск розрізняються.
- Основний і модальні графіки мають незалежне вікно з колесом та пресетами 7/30 днів; підсумки, таблиці й CSV лишаються за обліковим фільтром.
- Легенда деталей БпС має круглі маркери та нейтральні підписи зі збереженням керування серіями й окремої шкали FPV.
- Compact-картки категорій звужені; на телефоні дата модального графіка переноситься в окремий ряд, щоб показувати період повністю.
- `contour-compare.js` додає окремий аналітичний конструктор поверх чинного `ContourData`: до 6 серій із різних категорій/розділів, включно з FPV та типами БпС, без зміни Excel schema або внутрішньої aggregate math.
- Каталог показників у конструкторі згрупований за розділами та згортуваними категоріями; при першому відкритті всі категорії закриті, а вибрані за замовчуванням серії продовжують формувати графік.
- Вибір підрозділів винесений в окремий блок-дерево з `UNIT_HIERARCHY`: спочатку видно root-вузли, батьківський вузол можна вибрати за його власним рядком або розгорнути й вибрати конкретних нащадків.
- Parent і його descendant не можуть одночасно входити у comparison scope. Один вибраний вузол використовує власний `aggregate(..., group)`; кілька явно вибраних неперекривних вузлів формують суму їхніх власних серій для графіка. Якщо хоча б один вибраний вузол не має значення за день, composite-значення цього дня лишається `null / —`, без часткової суми.
- У панелі `Підрозділи` назва, цифровий лічильник та компактні кнопки `Усі / Скинути` візуально розташовані в одному рядку. Лічильник показує тільки число без `обр.`. `Усі` вибирає всі доступні кінцеві (leaf) вузли дерева без ancestor/descendant overlap; `Скинути` очищає unit scope. Окрема кнопка `Загальний підсумок` не відображається.
- Якщо після `Усі` або ручного вибору обрані всі доступні leaf-вузли певного parent-піддерева, parent візуально отримує checked-стан як агрегований індикатор повного складу. Такий derived checked-state **не додає parent у `selectedUnits`** і не змінює математику; зняття цього derived parent очищає його вибрані leaf-нащадки.
- У панелі `Показники` є окрема кнопка `Скинути`, яка очищає весь вибір показників. Кнопки дій у двох dropdown-панелях повторно використовують базовий dashboard-клас `.button` з компактним локальним розміром.
- Показники без підроздільної деталізації не отримують вигаданий unit filter і залишаються загальними.
- Конструктор має режими `Нормалізовано / Абсолютні`, `Лінія / Стовпчики`, ручний діапазон, 7/30 днів, копіювання періоду дашборда, керовану легенду та поденну таблицю.
- Перемикач типу графіка в конструкторі повторно використовує стандартний `segmented`-патерн інших графіків і має лише icon-only кнопки `trend / bars`; перемикач `Нормалізовано / Абсолютні` використовує той самий компактний segmented-стиль із текстовими назвами режимів. На mobile обидва перемикачі стоять в одному рядку, а chart toggle притиснутий до правого краю toolbar.
- Для нормалізації графіка перше доступне ненульове значення серії = 100; `null` не перетворюється на 0.
- Таблиця порівняння **завжди показує абсолютні значення джерела** і не змінюється при перемиканні `Нормалізовано / Абсолютні` на графіку.
- При активному unit scope таблиця використовує той самий hierarchy-патерн, що й «Деталі»: для кожної дати спочатку власний рядок кожного вибраного вузла, а якщо вузол є parent — одразу під ним тільки його безпосередні дочірні підрозділи, присутні в поточній книзі. Діти читаються власними `aggregate(..., group)` і не сумуються у parent.
- Глобальні показники при змішаному наборі виносяться в окремий рядок `Загальні показники`, щоб не приписувати їх кожному підрозділу.
- Таблиця порівняння повторно використовує `detail-hierarchy-table`, `detail-unit-parent`, `detail-unit-child`, а також чинний патерн `panel details-panel + table-wrap + table-foot`; custom max-height, типографіка або альтернативний table skin не задаються.
- У comparison workspace графік і таблиця працюють як взаємовиключний accordion: при відкритті конструктора графік розгорнутий, а секція `Деталі` згорнута. Розгортання `Деталі` автоматично згортає графік; повторне розгортання `Графік` автоматично згортає таблицю. Одночасно відкритою лишається тільки одна секція.
- Заголовок comparison-таблиці — `Деталі`. Поки таблиця згорнута, графік використовує збільшену висоту: до 480 px на desktop і 420 px на вужчих viewport; при відкритій таблиці графік не рендериться до повторного розгортання секції `Графік`.
- Модель конструктора завантажується ліниво з тієї самої книги та після локального імпорту повторно парситься тим самим `ContourData.parse()`; це окремий runtime-екземпляр без окремої семантики даних.
- На desktop кнопка `Порівняння` розташована праворуч у рядку перемикачів розділів. Сам workspace має три колонки: `Показники | Графік/параметри | Підрозділи`, тобто unit-фільтр розташований праворуч від графіка.
- На mobile нижня панель містить `Огляд / Розділи / Порівняння`; `Порівняння` відкривається як fixed-панель над нижньою навігацією, тому меню лишається видимим і клікабельним.
- На mobile блоки `Показники` та `Підрозділи` за замовчуванням приховані й викликаються окремими кнопками над workspace як dropdown overlay-панелі. Відкриття фільтра не зсуває графік або toolbar; одночасно активна лише одна панель, повторний клік її закриває. Висота overlay визначається вмістом (`auto`) з viewport-safe `max-height`; довгий список отримує власний вертикальний scroll і не перекриває нижню навігацію.

## Поточний фокус

Стабільний `main` містить інтегрований конструктор міжкатегорійного порівняння. Подальші зміни конструктора мають зберігати `UNIT_HIERARCHY`, Excel schema, normalized records і базову aggregate math без прямої потреби їх змінювати; для responsive/layout змін застосовувати відповідний change-scoped browser coverage.
