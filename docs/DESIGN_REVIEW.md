## Що вже створює характер

Графітова тема, Exo, малинові/сині серії, оливковий active-state, щільні панелі та один рухомий ряд карток уже утворюють впізнаваний інтерфейс. Це варто зберегти. Найсильніша можливість розвитку — зробити **аналітичну ієрархію виразнішою**: що обрано, яке головне значення, що змінилося, чим пояснюється результат.

Зараз заголовки, пояснення, фільтри й графіки часто мають близьку візуальну вагу. На телефоні до початку графіка доводиться пройти великий блок керування, тоді як самі інструкції й назви серій дуже дрібні. У конструкторі центральний графік губиться між широкими списками, а після звуження екрана фактично обрізається. Насамперед потрібні A01/A07/A08, інакше додаткові ефекти лише підсилять поточні проблеми читабельності.

## V1 · Виразніша типографіка та єдина система компонентів

**Пропозиція:** три виразні рівні поверхонь (canvas, panel, selected), чотири ролі тексту (title, value, label, supporting), спільні tokens відступів/радіусів/focus. Значення мають табличні цифри; вирівнювання десяткових чисел полегшує порівняння таблиць. Незначущі пояснення можна скоротити, зберігши точний зміст.

Орієнтовна стартова шкала для макета: 28–36 px для головних чисел, 16–18 для panel titles, 12–14 для змістовних підписів, 11–12 для метаданих. Це напрям для примірки, не універсальна вимога до кожного елемента. Великі числа не повинні виштовхувати другу складову парної картки.

**Візуальний ефект:** спокійніші поверхні, виразні числа, читабельні підписи. Поточні blue/red/gold/green мають зберігати свої аналітичні ролі; hover і selection не повинні підміняти колір серії.

**Критерій:** усі звичайні змістовні тексти мають контраст ≥4,5:1; немає обрізання при довгих назвах, від'ємних/дробових/великих значеннях. [W3C: Contrast Minimum](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html).

## V2 · Графік як головна робоча область

**Пропозиція:** окремо показувати обліковий період і вікно графіка, але компактно. Поруч із заголовком графіка — короткий ряд «Період → значення → зміна/баланс». Контекстні controls розміщувати в передбачуваних місцях: категорія графіка ліворуч, форма графіка праворуч.

Для comparison center має отримувати основну доступну ширину; бічні списки — визначені min/max, без порожніх колонок на невисокому ноутбуці. На touch повний графік і пояснення прокручуються разом у межах робочої панелі, нижня навігація залишається доступною.

**Аналітичне збагачення:** у normalized-порівнянні показати ненав'язливу горизонталь `100` і для кожної серії дату/абсолютне значення її бази. Це особливо корисно, коли перше ненульове значення різних серій припадає на різні дати. Tooltip може містити і абсолютне число, і індекс, із чіткими підписами; таблиця залишається абсолютною.

**Критерій:** графік повністю доступний на A01 viewport; користувач може пояснити значення індексу й визначити дату бази без пошуку в таблиці. Це окреме UX-розширення; чинну нормалізацію не змінювати.

## V3 · Порівняння з видимим складом вибірки

**Пропозиція:** короткий ряд вибраних серій з кольором, назвою й дією вилучення; короткий summary unit scope з розрізненням «власний рядок parent» і «сума N явно обраних вузлів». На mobile цей ряд може горизонтально прокручуватися, з доступними назвами кнопок.

Зараз вибрані серії сховані в згорнутих категоріях, а counter `3 / 6` не пояснює їхній склад. Після вибору шести показників UI має одразу пояснювати межу й спосіб заміни серії, а не лише приглушувати решту checkbox.

**Для дерева:** native buttons для відкриття filters; `mixed`-стан parent для часткового вибору, checked для повного піддерева. Візуальний derived state не додає parent до математичного scope. «Усі / Скинути» — одна операція стану й один render.

**Критерій:** сценарій «замінити одну з шести серій», ancestor/descendant selection, keyboard navigation і повернення focus проходять на desktop/tablet/phone. Колір збереженої серії не змінюється після вилучення сусідньої.

## V4 · Додаткова аналітика з наявних даних

Можливості нижче потребують окремого вибору обсягу. Вони не вимагають нового джерела чи передачі книги.

| Ідея | Що дає користувачу | Обмеження й критерій |
|---|---|---|
| Календарна смуга пропусків | Відразу видно, чому порівняння недоступне | Null має власне позначення, 0 — реальне значення; tooltip/таблична альтернатива доступні без мишки |
| Малі паралельні графіки | Зручно порівнювати форму різномасштабних серій | Масштаб кожної серії прямо підписаний; FPV відокремлений; це додатковий режим, а не заміна чинних графіків |
| Смуги відхилення від бази 100 | Чіткіше читається напрям зміни в normalized-порівнянні | Обчислення залишається чинним; базова дата відома; не називати індекс відсотком |
| Позначення максимуму/мінімуму | Миттєва опора для читання графіка | Позначаються лише реальні точки; для рівних максимумів потрібне зрозуміле правило; без довільних «аномалій» |
| Підсумок охоплення структури | Пояснює, яка частина source total показана | Спершу A06: явна політика невизначених вузлів, без реконструкції parent із дітей |

Кільця, gauges, 3D-карти й декоративні лічильники не пропонуються як нові обов'язкові елементи: для них у поточній моделі не задані цільові значення, географічні дані або окремий аналітичний сценарій. Візуальне збагачення має допомагати читати наявні числа.

## V5 · Рух, який пояснює дію

Зберегти стискання того самого sticky-ряду, не створювати compact-копії або spacer. Для filters, accordion і зміни series використовувати короткий узгоджений перехід, зберігаючи стабільну висоту робочої області. Не анімувати повторно весь графік після кожного checkbox із bulk-операції.

Reduced motion має вимикати як CSS transitions, так і JS-ініційований smooth scroll/оновлення chart. Видимий keyboard focus і touch-targets перевіряти окремо. Для важливих touch controls доречно приміряти 40–44 px зони натискання; формальний мінімум WCAG 2.5.8 — 24×24 px або передбачені винятки/відстані, а не універсальні 44 px. [W3C: Target Size Minimum](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html).

## Пропонований перший дизайн-пакет

Спершу **A01 + A07 + A08**, далі **V1 + V2**, потім **V3**. V4 — тільки після вибору конкретного аналітичного сценарію. Так можна отримати помітно сильніший інтерфейс, зберігши знайому навігацію, CRITICAL-математику й локальний режим.

Макет/реалізацію наступного етапу варто приймати на реальній контрольній книзі: звичайний період, доба з контекстом, null, нульова база, довга назва, шість серій, parent/children, ноутбук із малою висотою та телефон. Фото чи вигадані числа не замінюють ці перевірки.
