# Дані та розрахунки

Контракт підтверджений поточним адаптером і тестовою книгою. Зміна джерела потребує перевірки сумісності; числові рядки не конвертуються автоматично.

## Аркуші

| Аркуш | Нормалізований запис / використання |
|---|---|
| ГОЧ | date, row, group + поля з першого рядка заголовків; група в колонці B. Загальний ключ **`ВСЬОГО за СО:`** з двокрапкою |
| ОВгП | date, row, name, type, kind, groups[name]=[ВЗ,БП]; два рядки заголовків, парні числові колонки з E; загальний ключ **`ВСЬОГО за СО`** без двокрапки. Вартість виключена |
| Втрати ЗСУ | date + сімейства `*_доба`, `*_рік`, `*_всього`; добові суми окремо від останніх накопичених значень |
| Застосування БК та FPV | date + `Наші війська_БК`, `Противник_БК`, `Наші війська_FPV`, `Противник_FPV` |

Назви заголовків обрізаються й нормалізуються за пробілами. Дати: Excel serial, Date, ISO або DD.MM.YYYY / DD/MM/YYYY; внутрішній формат YYYY-MM-DD. Зсуви дат виконуються через UTC-полудень. Числа — тільки скінченний JS number, усе інше null. `sum([])` і сума з null → null.

## Відповідність операційних категорій

| Категорія | Поля → підписи |
|---|---|
| Обстріли | `Обстріли` |
| Ракетні удари | `Ракетні удари` → Удари; `Застосовано ракет` |
| АУ / КАБ / КАР | `АУ` → Авіаудари; `КАБ`; `КАР` |
| Штурмові дії | `Бойові зіткнення` → СОУ; `Штурмові дії` → Противник |
| Тривають зіткнення | `Тривають (бз)` → СОУ; `Тривають (шд)` → Противник |
| Позиції | `Всього втрачено позицій` → Втрачено; `Відновлено позицій` → Відновлено |
| Території | `відновлено_територій`; `втрачено_територій`. Баланс = перше − друге |
| Втрати особового складу | `Втрати_всього_ЗСУ` → СОУ; `Втрати_всього_рф` → Противник |
| БпС противника | Загальний `ВСЬОГО УДАРІВ БпЛА`; на картці FPV / інші БпС |

Території — «од. джерела», бо одиниця площі відсутня. Втрати — осіб, решта поточних категорій — од. СОУ синій, противник малиновий; відновлені позиції зелені. Об’єднані поля типів не дробити штучно.

БпС: `Шахеди/Гербера/Пародія`, `Італмас`, `Ланцет`, `Молнія`, `Бандероль`, `Привіт/Куб`, `FPV-дрони`. Синтетичне поле `БпС без FPV` — строга сума перших шести, незалежно від FPV і загального поля. Частки шести типів рахуються лише всередині цієї суми. Розбіжність із загальним полем показувати, не виправляти числа автоматично.

## Агрегація й повнота

ГОЧ: основна аналітика тільки загального рядка; таблиця містить і підсумки угруповань, і підрозділи, тому її рядки не можна додавати. Структура використовує УСБпС, Захід, 12 АК, Курськ, Північ, УОС, Схід, Південь — точні ключі в `groupNames` UI.

ОВгП фільтрується за type; підсумки з групи ВСЬОГО. Персонал: ВСЬОГО, безповоротні, санітарні, зниклі_безвісті, полон; накопичені беруться з останнього запису періоду, не підсумовуються.

`aggregate` будує календарні days, серії по кожному полю й totals за наявними відібраними rows. День present, коли хоча б одна серія не null; complete означає present===кількість календарних days. Це повнота наявності днів, не сертифікація кожної клітинки. Null конкретної складової все одно блокує її порівняння.

Період N днів порівнюється з N попередніми. Відсоток = (поточне − попереднє) / abs(попереднє) ×100. База 0 і поточне 0 → 0%; база 0 при ненульовому поточному → відсоток недоступний, пояснення про базу 0. Неповний період → недоступне порівняння. У неповному періоді підсумок може містити лише наявні rows із попередженням.

Контекст доби: початково −14/+15 днів, зміщується біля меж аркуша. Внутрішні пропуски залишаються null: 30 календарних позицій не означають 30 заповнених записів. Структура не є часовим графіком і залишається за вибраний період. У структурі смуги нормуються до найбільшого значення, відсотки — до суми показаних числових невід’ємних значень.
