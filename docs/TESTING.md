# Перевірки та запуск

Перевірки виконуються за ризиком зміни, а не за принципом «завжди перевірити все». Історію окремих ревізій тут не зберігати; детальні історичні проходи — у `.audit/REVISIONS.md`, короткий актуальний статус — у `CURRENT_STATE.md`.

## Запуск

Усі команди виконувати з кореня КОНТУРУ. Для локального сервера потрібен Python 3:

```sh
python -m http.server 8080 --bind 127.0.0.1
```

Відкрити `http://127.0.0.1:8080/`. Node.js потрібен лише для автоматичних JS/адаптерних перевірок. `npm install` для активного дашборду не потрібен. Не використовувати npm scripts вкладеного Dexie ToDo.

## Рівні перевірки

### LOW — локальна низькоризикова зміна

Застосовуй для тексту, локального CSS, невеликої функції або правки, що не змінює контракт даних, глобальний layout чи кілька модулів.

Мінімум:

- перевірити зачеплений сценарій;
- за зміни JS — відповідний `node --check`;
- за локальної UI-правки — один релевантний viewport;
- документаційна правка без runtime-змін не потребує runtime-тестів.

### NORMAL — зміна компонента або пов’язаної поведінки

Застосовуй для логіки одного компонента, кількох пов’язаних файлів, локальної зміни responsive-поведінки або графіків.

Мінімум:

- синтаксична перевірка змінених JS-файлів;
- релевантні функціональні сценарії;
- 1–2 viewport, якщо зміна залежить від ширини;
- `node .audit/verify-contour.cjs`, якщо зачеплено агрегацію, дати, поля, порівняння, FPV/типи або іншу логіку адаптера.

### FULL — крос-модульна або високоризикова зміна

Застосовуй для архітектури, моделі даних, глобального responsive/layout, великих рефакторингів, імпорту/експорту або змін із широким ризиком регресій.

Виконати за потреби:

```sh
node --check js/contour-data.js
node --check js/contour.js
node .audit/verify-contour.cjs
```

Для глобальних UI/layout-змін — три viewport-ревізії:

1. Desktop приблизно 1440×1000.
2. Планшет приблизно 1024×768.
3. Телефон приблизно 390×844; 320 px лише якщо зміна стосується вузької ширини.

Не запускати FULL лише через те, що зміна візуальна. Три viewport обов’язкові тільки коли правка потенційно впливає на кілька breakpoint або загальний layout.

## Сценарії за зачепленим модулем

Вибирай тільки релевантні сценарії:

- **Категорії/sticky:** стискання й розгортання того самого ряду, відсутність spacer/клонів, видимість активної картки, drag без випадкового click.
- **Дати:** доба/діапазон, перетин меж, рівність дат, неповні дані, контекст графіка не змінює підсумок.
- **Території:** баланс, нульова лінія, перемикання «Динаміка / Баланс».
- **БпС:** FPV та шість інших типів, незалежні масштаби, локальні line/bar, деталі й легенда.
- **Діалоги:** відкриття/закриття, Escape, фокус, повторні швидкі перемикання графіків.
- **Адаптивність:** drawer, нижня навігація, довгі назви, відсутність page overflow.
- **Доступність/анімація:** reduced motion, клавіатурний фокус, доступні назви кнопок.
- **Імпорт/CSV:** тільки якщо зміна торкається відповідних потоків.

## Автоматичний адаптерний тест

`node .audit/verify-contour.cjs` використовує локальний SheetJS і читає книгу без запису. Він перевіряє категорії, добові/періодні суми, null/0, помилки Excel, пари й типи БпС, незалежність FPV, контекст дат і нульову базу порівняння. Підсумковий PASS — завершення всього скрипта з exit 0.

`.audit/workbook_profile.py` — додатковий read-only профіль через openpyxl. Використовувати лише для задач джерела/структури книги.

## Технічні зауваження браузерної перевірки

- Після зміни кешованого CSS/JS переконайся, що браузер завантажив актуальний `?v=` ресурсу.
- Скріншот одразу після кліку може показувати попередній кадр; дочекайся завершення DOM/анімації.
- Timeout браузерного інструмента сам по собі не доводить помилку застосунку.
- Viewport-симуляція не є тестом на фізичному пристрої.
- Не записуй у цей файл результати кожного проходу; актуальний короткий статус — у `CURRENT_STATE.md`.
