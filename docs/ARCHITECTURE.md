# Архітектура

Актуалізовано: 2026-09-12. Проєкт зберігається у приватному GitHub-репозиторії. Активний КОНТУР залишається статичним застосунком без build-system, backend і package manager для runtime.

## Активний runtime

| Компонент | Відповідальність |
|---|---|
| `index.html` | DOM, доступні назви, підключення ресурсів, діалоги, шапка, dock, картки й панелі |
| `js/contour-data.js` | Excel-адаптер, метадані категорій, нормалізація, агрегація, контекст дат, порівняння |
| `js/contour.js` | Імпорт, стан, DOM, фільтри, графіки, таблиці, діалоги, CSV, scroll-поведінка |
| `css/contour.css` | Базова тема, компоненти, адаптивність |
| `css/contour-detail.css` | Парні показники й типи БпС |
| `css/contour-refinement.css` | Чинні уточнення щільності, навігації та анімації; завантажується останнім |
| `js/xlsx.full.min.js`, `js/apexcharts.js` | Локальні SheetJS та ApexCharts; CDN не потрібен |
| `fonts/`, `img/` | Локальні шрифти й зображення |
| `.audit/` | Адаптерні тести, профіль книги, історичні ревізії та початковий HTML |
| `Запустити.cmd` | Переносимий Windows launcher локального HTTP-сервера |

Основний потік: Excel → SheetJS.read → parse → доступні sections/categories → aggregate вибраного періоду → картки/структура/таблиця/focus/CSV. Для часових графіків окремо: contextRange → aggregate → ApexCharts. Для деталей угруповання використовується його ключ, а не загальний підсумок.

## Репозиторій і версіонування

- `main` — перевірений базовий стан.
- Значущі зміни виконуються в окремих гілках і після перевірки зливаються в `main`.
- Git-історія замінює ручні каталоги `versions`, `txt v 1`, `txt v 2` та інші копії старого коду.
- `.gitignore` відсікає локальні кеші, IDE-файли, build-артефакти, секрети й Office temp-файли.
- `.gitattributes` фіксує text/binary класифікацію та CRLF для `.cmd`.
- Неактивні MVC/Dexie-шари, дубль `xlsx.js`, старий `css.css` і непідключений Bootstrap вилучені з активного дерева; історія доступна через Git.

## Стан і рендер

Стан живе в замиканні `contour.js`: дані, розділ/категорія, from/to, тип графіка, territory-режим, тип БпС, складова структури, таблиця та об’єкти графіків. Активних IndexedDB, localStorage, backend або service worker немає; reload скидає імпорт і фільтри.

`render()` перебудовує релевантний DOM, знищує старі основні графіки й створює нові; generation відсікає застаріле асинхронне завершення. Графіки діалогів мають окремий lifecycle і знищуються при закритті. Відхилення Promise основних графіків зараз поглинаються через `allSettled` без окремого UI помилки — технічний борг.

## Навігація, sticky та анімація

Один `#metrics` постійно розміщений у sticky `#workspace-dock`. `#dock-anchor` і scroll handler у `requestAnimationFrame` визначають pinned-стан; `is-scrolled` ущільнює шапку, `cards-away` змінює розміри тих самих карток через CSS transitions. Окремого compact-ряду та компенсаційного spacer у DOM немає.

`updateRail` керує масками країв і горизонтальним прокручуванням; `followCategory` підсуває ряд лише біля останніх двох видимих наступних карток або коли активна картка поза екраном. `dragRail` використовує pointer capture і пригнічує click після drag.

`categorySizeLock` зберігає розгорнутий/компактний стан під час програмного повернення `selectCategory` до `scrollY=0`; lock знімається після повернення до природного pinned-стану.

Для карток типів БпС `dockScroll`, `ResizeObserver` і `compressDrones` керують поступовим стисканням. `arrangeDroneRow` анімує переміщення тих самих DOM-карток у компактний горизонтальний ряд без spacer. `reduced motion` вимикає часову анімацію; CSS-стискання не запускає повторну агрегацію даних.

Бічна панель прихована CSS на desktop/landscape, але її DOM і частина обробників залишаються. На малих екранах діють drawer і нижня навігація. Не видаляти прихований DOM без перевірки залежних JS-селекторів.

## Графіки та деталі БпС

Адаптер надає `axisRange` для локального масштабу мініграфіків та `integerAxis` для цілих поділок основних/модальних осей. Сім карток БпС створює `renderDroneTypes`; локальні area/bar режими незалежні від головного `chartType`.

`showDroneDetail` агрегує сім типів за `row.name`: підсумки/таблиця використовують from/to, графік — contextRange. `mountDetailTrend` керує локальним line/bar режимом і множиною вибраних типів. При спільному показі FPV має незалежну праву вісь, інші типи — ліву.

## Імпорт, експорт і запуск

- Початковий fetch — сусідня `Накопичення.xlsx`; далі File API для `.xlsx/.xls/.xlsm`, межа 30 MiB.
- Parser вимагає заповнений ГОЧ або ОВгП; книга лише з персоналом/БК наразі не проходить загальну перевірку імпорту.
- Формули не перераховуються; використовуються збережені значення.
- ОВгП читається за фіксованими парами колонок після двох рядків заголовків.
- Ручний діапазон відхиляється при різниці дат >366 днів; «увесь період» обходить цю перевірку. В aggregate є окремий захист близько 4001 дати.
- CSV: UTF-8 BOM, `;`, CRLF, лапки; null → порожнє поле; початкові `= + @ -` екрануються апострофом. Експорт — Blob/object URL без сервера.
- `Запустити.cmd` шукає Python 3 через `py -3`, `python` або `python3`, відкриває браузер і запускає `http.server` лише на `127.0.0.1:8080`.
- `?v=28` — ручний cache busting, не semver.

## Зони великого впливу

Широкої перевірки потребують зміни в: відборі колонок і ключах загальних рядків; null-агрегації; розмежуванні period/context; CSV; lifecycle ApexCharts; глобальному sticky/responsive layout; каскаді трьох CSS.

Продуктивність: на кожен render є повторні фільтри `rows × days × categories`; великий імпорт обробляється в головному потоці. Виміряного бюджету продуктивності й автоматичного browser-suite немає.
