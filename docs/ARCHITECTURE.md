# Архітектура

Актуалізовано: 2026-09-12. Проєкт зберігається у приватному GitHub-репозиторії. Активний КОНТУР — статичний застосунок без build-system, backend і package manager для runtime.

## Активний runtime

| Компонент | Відповідальність |
|---|---|
| `index.html` | DOM, доступні назви, підключення ресурсів, діалоги, шапка, dock, картки й панелі |
| `js/contour-config.js` | `APP_CONFIG`, `WORKBOOK_SCHEMA`, перелік основних угруповань, типи джерел і централізовані runtime-константи |
| `js/contour-data.js` | Перевірка Excel-контракту, parse/normalization, метадані категорій, агрегація, date policy, контекст дат і порівняння |
| `js/contour.js` | Імпорт, runtime state, DOM, фільтри, графіки, таблиці, діалоги, CSV, source state і scroll-поведінка |
| `css/contour.css` | Базова тема, компоненти, адаптивність |
| `css/contour-detail.css` | Парні показники й типи БпС |
| `css/contour-refinement.css` | Чинні уточнення щільності, навігації та анімації; завантажується останнім |
| `js/xlsx.full.min.js`, `js/apexcharts.js` | Локальні SheetJS та ApexCharts; CDN не потрібен |
| `fonts/`, `img/` | Локальні шрифти й зображення |
| `.audit/` | Адаптерні/regression перевірки, профіль книги, історичні ревізії та початковий HTML |
| `Запустити.cmd` | Переносимий Windows launcher локального HTTP-сервера |

Основний потік тепер: **Excel → SheetJS.read → validateWorkbook → parse/normalize → sections/categories → aggregate → UI**. Критичні помилки схеми зупиняють імпорт до побудови моделі; некритичні відхилення зберігаються як validation warnings і показуються користувачу.

Для часових графіків: `contextRange → aggregate → ApexCharts`. Для деталей угруповання використовується його ключ, а не загальний підсумок.

## Конфігурація та Excel-контракт

`contour-config.js` є єдиним runtime source of truth для:

- назви bundled workbook і ліміту імпорту;
- типів джерел `bundled` / `user`;
- політики дат;
- назв підтримуваних аркушів;
- спеціальних підсумкових рядків ГОЧ/ОВгП;
- полів категорій і типів БпС;
- переліку основних угруповань для структури.

`contour-data.js` не дублює ці назви в алгоритмах. `validateWorkbook()` формує `errors` і `warnings`; `parse()` при критичній несумісності кидає `WorkbookValidationError` із деталями validation.

## Джерело даних

Runtime зберігає джерело як `{ kind, name }`. Filename більше не визначає, чи є книга bundled/test data. Автоматично завантажена сусідня книга має `kind: bundled`; будь-який файл через File API — `kind: user`, навіть якщо його назва збігається з `Накопичення.xlsx`.

## Дати

Політика дат централізована в `APP_CONFIG.datePolicy`:

- ручний діапазон — максимум 366 **включних календарних днів**;
- однакова from/to — 1 день;
- контекст обраної доби — до 30 календарних позицій (-14/+15 зі зміщенням біля меж джерела);
- aggregate має safety cap 4001 календарна позиція й повертає ознаку `truncated`, якщо запит довший.

Preset «Увесь період» не є ручним введенням і може охоплювати ширший інтервал; safety cap залишається внутрішньою межею агрегатора.

## Стан і рендер

Стан живе в замиканні `contour.js`: дані, `source`, розділ/категорія, from/to, тип графіка, territory-режим, тип БпС, складова структури, таблиця та об’єкти графіків. Активних IndexedDB, localStorage, backend або service worker немає; reload скидає імпорт і фільтри.

`render()` перебудовує релевантний DOM, знищує старі основні графіки й створює нові. `generation` відсікає застаріле асинхронне завершення. Якщо актуальний ApexCharts render відхиляється, chart host отримує видимий error-state, а таблиці/числові дані залишаються доступними. Графіки діалогів мають окремий lifecycle, видимий error-state та знищуються при закритті.

## Навігація, sticky та анімація

Один `#metrics` постійно розміщений у sticky `#workspace-dock`. `#dock-anchor` і scroll handler у `requestAnimationFrame` визначають pinned-стан; `is-scrolled` ущільнює шапку, `cards-away` змінює розміри тих самих карток через CSS transitions. Окремого compact-ряду та компенсаційного spacer у DOM немає.

`updateRail` керує масками країв і горизонтальним прокручуванням; `followCategory` підсуває ряд лише біля останніх двох видимих наступних карток або коли активна картка поза екраном. `dragRail` використовує pointer capture і пригнічує click після drag.

`categorySizeLock` зберігає розгорнутий/компактний стан під час програмного повернення `selectCategory` до `scrollY=0`.

Для карток типів БпС `dockScroll`, `ResizeObserver` і `compressDrones` керують поступовим стисканням. `arrangeDroneRow` анімує переміщення тих самих DOM-карток у компактний горизонтальний ряд без spacer. `reduced motion` вимикає часову анімацію.

Бічна панель прихована CSS на desktop/landscape, але її DOM і частина обробників залишаються. На малих екранах діють drawer і нижня навігація.

## Графіки та деталі БпС

Адаптер надає `axisRange` для локального масштабу мініграфіків та `integerAxis` для цілих поділок основних/модальних осей. Сім карток БпС створює `renderDroneTypes`; локальні area/bar режими незалежні від головного `chartType`.

`showDroneDetail` агрегує сім типів за `row.name`: підсумки/таблиця використовують from/to, графік — contextRange. `mountDetailTrend` керує локальним line/bar режимом і множиною вибраних типів. При спільному показі FPV має незалежну праву вісь, інші типи — ліву.

## Імпорт, експорт і запуск

- Початковий fetch — `APP_CONFIG.defaultWorkbook`; далі File API для `.xlsx/.xls/.xlsm`, межа з `APP_CONFIG.maxImportBytes`.
- Загальна acceptance policy вимагає заповнений ГОЧ або ОВгП; книга лише з персоналом/БК наразі не проходить імпорт.
- Формули не перераховуються; використовуються збережені значення.
- ОВгП читається за фіксованими парами колонок після двох рядків заголовків.
- CSV: UTF-8 BOM, `;`, CRLF, лапки; null → порожнє поле; початкові `= + @ -` екрануються апострофом.
- `Запустити.cmd` шукає Python 3 через `py -3`, `python` або `python3`, відкриває браузер і запускає `http.server` лише на `127.0.0.1:8080`.
- JS runtime у Stage 2 має cache revision **29**; CSS refinement лишається revision 28, бо CSS не змінювався.

## Репозиторій і версіонування

- `main` — перевірений базовий стан.
- Значущі зміни виконуються в окремих гілках і після перевірки зливаються в `main`.
- Git-історія замінює ручні каталоги версій і копії старого коду.
- `.gitignore` відсікає локальні кеші, IDE-файли, build-артефакти, секрети й Office temp-файли.
- `.gitattributes` фіксує text/binary класифікацію та CRLF для `.cmd`.

## Зони великого впливу

Широкої перевірки потребують зміни в `WORKBOOK_SCHEMA`, acceptance policy, ключах загальних рядків, null-агрегації, date policy, period/context, CSV, lifecycle ApexCharts, глобальному sticky/responsive layout і каскаді трьох CSS.

Продуктивність: на кожен render залишаються повторні фільтри `rows × days × categories`; великий імпорт обробляється в головному потоці. Кеш/індекси агрегацій належать до наступного етапу. Виміряного бюджету продуктивності й автоматичного browser-suite поки немає.
