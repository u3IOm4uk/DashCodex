# КОНТУР

Локальний український аналітичний дашборд на основі **«Накопичення.xlsx»**: періоди, порівняння, структура, графіки, деталізація та CSV.

## Як продовжувати роботу

Для Codex/нової сесії не потрібно читати всю документацію. Початковий мінімум:

1. [AGENTS.md](AGENTS.md) — правила роботи й маршрутизація контексту.
2. [CURRENT_STATE](docs/CURRENT_STATE.md) — короткий фактичний стан.
3. Код модуля, якого стосується задача.

Решту документів відкривати лише за тематикою задачі:

| Документ | Канонічна роль |
|---|---|
| [PROJECT_SPEC](docs/PROJECT_SPEC.md) | Чинні вимоги, UX/бізнес-правила та CRITICAL-контракти |
| [ARCHITECTURE](docs/ARCHITECTURE.md) | Активні модулі, потоки, lifecycle, запуск і технічні межі |
| [DATA_MODEL](docs/DATA_MODEL.md) | Excel-контракт, агрегація, validation, null, дати й семантика даних |
| [DECISIONS](docs/DECISIONS.md) | Значущі довготривалі рішення та їх заміни |
| [TESTING](docs/TESTING.md) | Ризик-орієнтовані рівні й сценарії перевірки |

| [CURRENT_STATE](docs/CURRENT_STATE.md) | Поточна реалізація, ключові обмеження, фокус і останній релевантний статус перевірок |

Історія ітерацій та старі перевірки не є робочим контекстом: вони зберігаються в `.audit/REVISIONS.md` та Git-історії.

## Git/GitHub workflow

Канонічна версія проєкту зберігається у приватному GitHub-репозиторії. `main` має містити лише перевірений стан. Для значущих змін створюється окрема гілка, після перевірки зміни зливаються в `main`.

На іншому ПК: спочатку `git pull`, після роботи — перевірити diff, виконати потрібні тести, зробити commit і `git push`. Код, документація та Git-історія є джерелом стану проєкту, а не історія чату.

## Запуск

На Windows рекомендований спосіб — подвійний клік по `Запустити.cmd`. Скрипт переходить у корінь проєкту, шукає Python 3 через `py -3`, `python` або `python3`, відкриває `http://127.0.0.1:8080/` і запускає HTTP-сервер лише на localhost.

Ручний запуск:

```sh
python -m http.server 8080 --bind 127.0.0.1
```

Активний дашборд не потребує `npm install` або build-системи. Без HTTP-сервера можна відкрити `index.html` і вручну імпортувати книгу; автоматичне завантаження сусідньої книги може блокувати браузер.

## Активна структура

Runtime складається з:

- `index.html` — чинний DOM та підключення ресурсів;
- `js/contour-config.js` — Excel/runtime/date/performance config;
- `js/contour-data.js` — validation, parse/normalization, lazy indexes, aggregate cache, агрегація й date helpers;
- `js/contour-view.js` — pure formatting/escaping/icon helpers;
- `js/contour-charts.js` — pure chart option/SVG builders;
- `js/contour.js` — state, DOM orchestration, import/export, navigation, dialogs і chart lifecycle;
- `js/xlsx.full.min.js`, `js/apexcharts.js` — локальні сторонні бібліотеки;
- три `contour*.css`, `fonts/`, `img/` і `Накопичення.xlsx`.

Перед `parse()` книга проходить структурну перевірку. Parsed-модель використовує lazy indexes і bounded LRU aggregate cache; новий імпорт отримує ізольований cache. Це оптимізація повторних обчислень, а не зміна аналітичної математики.

Legacy hidden sidebar і старий donut-host вилучені з runtime DOM. Desktop/tablet мають видимий доступ до «Джерело» в шапці, mobile — через нижню навігацію. Якщо у структурі частина значень відсутня, UI явно пояснює, що `null` не прирівнюється до нуля.

## Важливо

Книга не перезаписується й не надсилається зовнішнім сервісам. Імпорт і фільтри живуть лише до перезавантаження. Дані тестові, дати аркушів різні; у вартості ОВгП є помилки джерела, одиниця площі територій не вказана.

Початковий HTML — `.audit/index.original.html`. Історичні матеріали не замінюють чинну специфікацію й поточний стан.
