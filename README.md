# КОНТУР

Локальний український аналітичний дашборд на основі **«Накопичення.xlsx»**: періоди, порівняння, структура, графіки, деталізація та CSV.

## Git/GitHub workflow

Канонічна версія проєкту зберігається у приватному GitHub-репозиторії. `main` має містити лише перевірений стан. Для значущих змін створюється окрема гілка, після перевірки зміни зливаються в `main`.

На іншому ПК: спочатку `git pull`, після роботи — перевірити diff, виконати потрібні тести, зробити commit і `git push`. Код, документація та Git-історія є джерелом стану проєкту, а не історія чату.

## Запуск

На Windows рекомендований спосіб — подвійний клік по `Запустити.cmd`. Скрипт переходить у корінь проєкту, шукає Python 3 через `py -3`, `python` або `python3`, відкриває `http://127.0.0.1:8080/` і запускає HTTP-сервер лише на localhost.

Ручний запуск:

```sh
python -m http.server 8080 --bind 127.0.0.1
```

Активний дашборд не потребує `npm install` або build-системи. Без HTTP-сервера можна відкрити `index.html` і вручну імпортувати книгу; автоматичне завантаження сусідньої книги може блокувати браузер.

## Активна структура

Runtime складається з:

- `index.html` — чинний DOM і підключення ресурсів; поведінка comparison controls міститься в модулі;
- `js/contour-config.js` — Excel/runtime/date/performance config;
- `js/contour-data.js` — validation, parse/normalization, lazy indexes, aggregate cache, агрегація й date helpers;
- `js/contour-units.js` — представлення ієрархії з `UNIT_HIERARCHY`, розгортання та локальні статуси підрозділів;
- `js/contour-navigation.js` — навігація категорій зі збереженням sticky/compact стану;
- `js/contour-view.js` — pure formatting/escaping/icon helpers;
- `js/contour-charts.js` — pure chart option/SVG builders;
- `js/contour.js` — state, DOM orchestration, import/export, navigation, dialogs і chart lifecycle;
- `js/contour-compare.js` — окремий UI/runtime конструктора міжкатегорійного порівняння: каталог до 6 серій, незалежний період, unit scope, нормалізований/абсолютний графік і hierarchy-таблиця поверх чинних `ContourData.parse()` / `aggregate()`;
- `js/xlsx.full.min.js`, `js/apexcharts.js` — локальні сторонні бібліотеки;
- `css/contour-compare.css` — триколонковий desktop layout та mobile picker/fixed-panel поведінка конструктора порівняння;
- інші чотири `contour*.css`, `fonts/`, `img/` і `Накопичення.xlsx`.

Перед `parse()` книга проходить структурну перевірку. Parsed-модель використовує lazy indexes і bounded LRU aggregate cache; новий імпорт отримує ізольований cache. Це оптимізація повторних обчислень, а не зміна аналітичної математики.

Конструктор порівняння не змінює основний analytics state або Excel-схему. Він ліниво працює з тією самою локальною книгою через той самий `ContourData`-контракт; нормалізація є лише presentation-transform для графіка, а таблиця зберігає абсолютні значення джерела.

`ContourSource` надає обом інструментам одну прийняту модель: відкриття порівняння зберігає дерево огляду, а невалідний імпорт — попередні дані. Порівняння має доступні клавіатурні фільтри, прокручуваний графік і підписи баз нормалізації. Quality router включає comparison specs; повний infrastructure scope автоматично знаходить усі browser specs. Поточний статус реалізації й перевірок — у [CURRENT_STATE](docs/CURRENT_STATE.md).

Legacy hidden sidebar і старий donut-host вилучені з runtime DOM. На mobile нижня навігація містить `Огляд / Розділи / Порівняння`; порівняння відкривається над нею без приховування нижнього меню. Якщо у структурі частина значень відсутня, UI явно пояснює, що `null` не прирівнюється до нуля.

## Важливо

Книга не перезаписується й не надсилається зовнішнім сервісам. Імпорт і фільтри живуть лише до перезавантаження. Статуси видимості й архіву підрозділів зберігаються в localStorage як локальні налаштування UI; дані книги не зберігаються в ньому. Дані тестові, дати аркушів різні; у вартості ОВгП є помилки джерела, одиниця площі територій не вказана.

Початковий HTML — `.audit/index.original.html`. Історичні матеріали не замінюють чинну специфікацію й поточний стан.
